# Ingestion: spreadsheet imports and future integrations (Prompt 3)

Data enters the platform three ways, and all three go through the same rules:

| Provenance | How it arrives | Status |
|---|---|---|
| `MANUAL` | Typed in the app (`POST /v1/events`) | Built (Block 2) |
| `IMPORTED` | CSV or .xlsx uploaded to `POST /v1/imports` | Built (this block) |
| `VERIFIED` | Read from a system of record (SEFAZ NF-e, a registry, machine telemetry) | Designed only, see below |

Every event's record (`GET /v1/events/{id}` and the timelines) shows `provenance` and `importBatchId`.

## Locked choices

| Area | Choice | Alternatives considered |
|---|---|---|
| File formats | CSV (`;` or `,`, UTF-8 or Windows-1252, detected automatically) and .xlsx | CSV only; Google Sheets API |
| Processing | Inside the request, up to 2,000 rows; dry run first | Background job with progress; streaming |
| Templates | .xlsx generated by the API per caller | Static files in the repo; a front-end grid |
| Errors | JSON per row, plus a downloadable copy of the file with an `erro` column | JSON only; email report |
| Libraries | `csv-parse`, `exceljs` | SheetJS (licence changes), papaparse |

## How an import works

1. **Download the template:** `GET /v1/imports/templates/{kind}`. The workbook has three sheets:
   - **Dados**: Portuguese headers (`*` marks required columns) and dropdowns.
   - **Instruções**: every column with its format, an example and notes, plus an example row.
   - **Referência**: the farms, plots, seasons, checklist items and evidence files *this caller* may cite.
2. **Validate:** `POST /v1/imports` with `kind`, `file` and `dryRun=true` (the default). Every row runs inside a transaction, each in its own savepoint, so all errors are reported at once. Then everything is rolled back.
3. **Fix:** `GET /v1/imports/{id}/annotated` returns the same rows with an `erro` column and the bad rows in red. Fix them in Excel and upload again.
4. **Apply:**
   - Call `POST /v1/imports/{id}/apply` to apply a clean dry run from its stored rows, without uploading again.
   - Or upload with `dryRun=false`.
   - **A batch applies whole or not at all.** One bad row means `FAILED`, and nothing is written.
5. **Undo:** call `POST /v1/imports/{id}/rollback`, which works only before `rollbackAvailableUntil` (see "Rollback").

### Same rules as manual entry

Each row becomes canonical events, which go through `parseEvent` and then `recordEventTx`, the same path as `POST /v1/events`. That path covers:
- role and organization checks
- the emitter matrix
- the state machine
- the CPR's designated warehouse
- the evidence check
- CAR uniqueness

The importer itself adds only lookups (names to ids) and unit conversions.

### Idempotency

- Event ids (and new plot ids) are UUID version 8, derived from each row's natural key, so **uploading the same file twice writes nothing the second time**. Those rows count as `unchangedRows`.
- A row that changed since it was imported is reported: *"Linha já importada com outros valores; corrija pelo app"*. Corrections go through `EVENT_CORRECTED`, never a re-import.

| Kind | Natural key |
|---|---|
| PLOTS | farm + plot name |
| PLANTINGS | crop cycle (one planting per cycle) |
| INPUT_APPLICATIONS | cycle + date + category + product |
| DELIVERIES | cycle + plate + dispatch date and time; stages already recorded are skipped |

### Values

| What | Accepted |
|---|---|
| Numbers | `1.234,56`, `250,5`, `37.000` (thousands), `12.5`, and Excel numbers. A single dot followed by exactly three digits is a thousands separator |
| Dates | `dd/mm/aaaa`, `aaaa-mm-dd`, Excel date cells. `dd/mm/aa` is refused |
| Times | `hh:mm`, `14h30`, Excel time cells. São Paulo time (UTC−3) |
| Area | hectares, stored as whole m² |
| Liquids | `L` is converted to `mL`; `KG` and `ML` must be whole numbers |
| Headers | Case, accents, spaces and the `*` are ignored (`Área (ha) *` = `area_ha`). Unknown columns, such as `erro`, are ignored |
| Plot | `Fazenda / Talhão` from the reference sheet, the plot id, or the plot name when it is unique among the caller's plots |
| Season | `2026/27-SAFRA`, `2026/27 safra` or `2026/27 Safrinha` |
| Evidence | The file name it was uploaded with (`POST /v1/files` now stores it), or its SHA-256 |

## Kinds and who may import them

| Kind | Roles | Writes | Notes |
|---|---|---|---|
| `PLOTS` | PRODUCER, ADMIN | `PLOT_REGISTERED` | Farms are created in the app. UF and municipality default to the farm's |
| `PLANTINGS` | PRODUCER, ADMIN | `PLANTING_RECORDED` | The crop cycle must already exist (it needs the expected yield, which sets the CPR cap) |
| `INPUT_APPLICATIONS` | PRODUCER, ADMIN | `INPUT_APPLICATION_RECORDED` | Evidence is required. If no checklist item is given, the only item of that category is used; if there are several, the row asks for one |
| `DELIVERIES` | PRODUCER, WAREHOUSE, ADMIN | `TRUCK_DISPATCHED`, `TRUCK_ARRIVED`, `GRAIN_RECEIVED` | One truck per row, with whatever stages it has. Without a dispatch date, the truck is matched by plate among the cycle's open deliveries. A blank discount is computed from the discount table; a net weight given must equal gross − discount. Each stage still needs its role, so a warehouse can't dispatch |
| `PLANTING_WINDOWS` | ADMIN | config table | **Replaces the whole table** with the file. An empty file is refused |
| `DISCOUNT_TABLES` | ADMIN | config table | Replaces the whole table; one row per crop |

Config imports are written to the audit log like `PUT /v1/config/*`, and alerts are recomputed for every cycle.

## Rollback

- **The problem:** the anchoring worker is woken as soon as events are recorded, so imported events would reach the chain within seconds and a rollback would almost never be possible.
- **The fix:** imported events wait `IMPORT_HOLD_MINUTES` (default 30) before anchoring. Anything recorded later on the same plot or cycle waits behind them, to keep the chain's order.
- **The deadline:** rollback closes 1 minute before the hold ends (`rollbackAvailableUntil`), so a rollback can never race the relayer.

A rollback is refused when:

| Case | Code |
|---|---|
| Any event in the batch was already sent to the chain, or the window closed | `BATCH_ALREADY_ANCHORED` |
| An event recorded later on the same plot or cycle, a correction pointing at the batch, or a crop cycle created on an imported plot | `BATCH_HAS_DEPENDENTS` |
| A config table was edited after the import | `BATCH_HAS_DEPENDENTS` |

A rollback deletes the batch's events, removes plots it created, replays the affected crop cycles, and re-syncs their alerts. After the window closes, fix data with `EVENT_CORRECTED` or `EVENT_VOIDED`, as for manual entries.

## The `IngestionSource` port

```ts
interface IngestionSource {
  name: string;               // "SPREADSHEET" today
  provenance: Provenance;     // IMPORTED; VERIFIED for systems of record
  rows(): Iterable<SourceRow>; // { n, values: Map<columnKey, cell> }
}
```

A source only yields rows. Mapping rows to canonical events (`kinds.ts`), validating them, and the batch, savepoint, rollback and annotated-file machinery are shared. A new feed needs a source and, if its shape is new, a kind; it never needs a new write path.

| File | Role |
|---|---|
| `parse.ts` | CSV/XLSX reading, encoding and separator detection, pt-BR numbers, dates and times |
| `source.ts` | `IngestionSource`, `spreadsheetSource`, `RowReader` (collects every error in a row), deterministic `importId` |
| `reference.ts` | What the caller may cite, plus name-to-id lookups |
| `kinds.ts` | Columns and row mapping for each kind |
| `workbook.ts` | Templates and the annotated file |
| `../services/imports.ts` | Running batches, apply, rollback, views |

## Future integrations (design only, not built)

| System | Gives us | Provenance | How | Kind / event | Notes |
|---|---|---|---|---|---|
| Digital twin (existing) | Plot geometry, soil analyses | VERIFIED | Pull by `digitalTwinRef` on the plot | `SOIL_ANALYSIS_ATTACHED`, plot geometry | First to build: the reference column already exists on plots |
| SICAR / CAR | Property boundary, CAR status (active, pending, cancelled) | VERIFIED | SICAR public consultation by CAR code | Plot check, not an event | Flags a CAR that is cancelled or overlaps another plot |
| ZARC (MAPA) | Official planting windows by crop, municipality and soil | VERIFIED | Download the official tables per crop and season | `PLANTING_WINDOWS` | Replaces the `isSample` windows |
| Weather (INMET, private providers) | Rain and frost around planting and harvest | VERIFIED | Daily pull per municipality | New finding, not an event | Explains a late planting or a lower yield in the risk view |
| NDVI / satellite | Crop emergence, vigour, harvest detection | VERIFIED | Provider API per plot polygon | Finding: "planting not seen" or "harvest seen before HARVEST_STARTED" | Needs plot polygons |
| Telemetry (harvesters, trucks) | Harvest start and truck GPS | VERIFIED | Manufacturer or fleet APIs, webhooks | `HARVEST_STARTED`, `TRUCK_DISPATCHED`, `TRUCK_ARRIVED` | Matches plates and plots |
| NF-e (SEFAZ) | Input invoices and grain shipping invoices | VERIFIED | Consult by 44-digit key (certificate needed) | Confirms `INPUT_APPLICATION_RECORDED` (`nfeKey`) and deliveries | Turns a typed key into proof |
| Warehouse WMS / scale system | Scale tickets and classification | VERIFIED | Export file (reuses `DELIVERIES`) or API | `TRUCK_ARRIVED`, `GRAIN_RECEIVED` | Most likely first real integration after the pilot |
| CPR registries (B3, CERC) | Official CPR registration number and status | VERIFIED | Registry API | `CPR_ISSUED` reference | Needed before any legal use (verify with counsel) |
| Lenders and insurers | Disbursements, claims | VERIFIED | Webhook or file | `FUNDING_DISBURSED`; new event for claims | Spec change needed for claims |

Rules for every integration:
- It writes only through `recordEventTx`.
- It uses deterministic ids from the source's own key, so a re-sync is idempotent.
- It never overwrites a manual record: a disagreement becomes a finding or an alert.
- It keeps the source document's hash as `evidenceHash`.

## Data-quality checklist (before the pilot)

- [ ] Farms created for every producer, with the right UF and IBGE municipality.
- [ ] Plot areas in hectares, not alqueires: 1 alqueire paulista is 2.42 ha, and 1 alqueire mineiro or goiano is 4.84 ha.
- [ ] CAR codes copied from the CAR receipt, not typed from memory. A CAR already used by another producer is refused.
- [ ] Crop cycles created in the app, with the expected yield from the agronomist, before plantings or applications are imported.
- [ ] Planting windows and discount tables replaced with official ZARC data and the warehouse's real table. Rows marked `Amostra = sim` are test data.
- [ ] Evidence files (invoices, prescriptions, tickets) uploaded before the applications that cite them, each with a clear file name.
- [ ] Plates in `ABC1D23` or `ABC1234` form. Dates are the day the event happened, not the day it was typed.
- [ ] Gross, discount and net weights from the scale ticket. Leave the discount blank only if the warehouse uses the table on file.
- [ ] Every file run as a dry run first. The batch was checked in the timeline before the 30-minute window closed.
- [ ] One person per organization owns imports, so rollbacks and corrections have a clear owner.

## Known limits

- Processing happens inside the request: 2,000 rows is about the ceiling before a request takes too long. Bigger files need a background job.
- Every event replays its subject's whole stream, so a single cycle with hundreds of rows in one batch gets slower. That is fine at pilot volumes.
- Crop cycles and CPR requests can't be imported, on purpose: they set the volume cap and need a human decision.
- Row errors are in Portuguese. When a business rule rejects a row, the error also carries the API's code and its English detail, so the front-end can translate.
